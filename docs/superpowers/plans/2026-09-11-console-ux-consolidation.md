# Console UX and DX Consolidation Implementation Plan

**Goal:** Reduce console navigation and workflow friction while making validation, sensitive data, operational detail, and destructive actions trustworthy and consistent.

**Architecture:** Consolidate related screens into task-oriented hubs without merging distinct backend models. Keep existing data hooks and focused body components, introduce compatibility redirects for old URLs, and store shareable UI state in the URL. Deliver each task test-first with atomic commits.

**Tech stack:** React 19, TypeScript, TanStack Router and Query, Tailwind CSS, Motion, Vitest, Testing Library.

## Global Constraints

- Work only in the existing isolated feature worktree, never directly on `main`.
- Use strict red-green-refactor TDD for every behavior change.
- Preserve old dashboard URLs through redirects or compatibility route wrappers.
- Never silently ignore an invalid submit. Mark submitted fields touched, show an inline specific error, focus the first invalid field, and preserve values after API errors.
- Use toasts for global or asynchronous failures, not as a replacement for field errors.
- Sensitive plaintext values are masked by default, copyable without revealing, explicitly revealable, and cleared from UI state on dismissal.
- Animations must respect reduced-motion preferences.
- Existing API models remain authoritative. Do not invent unavailable instance telemetry or debugger diagnoses.
- Important selections, filters, and detail identifiers must be deep-linkable when a route owns them.
- Generated route-tree files are regenerated by project tooling, not manually edited.
- Keep commits atomic and run focused tests before every commit. Run `npm run build` and `npm run check` before branch completion.

## Task 1: Form reliability and trust fixes

**Files:** `src/components/ui/field.tsx`, targeted dashboard route files and their tests, account query/mock handlers where required.

- Add the smallest reusable field-validation helpers needed for submit attempts, inline errors, accessibility attributes, and first-invalid focus.
- Fix empty Domain submission and cover it with a failing regression test first.
- Migrate invitations, Cron schedules, API-key grace window, Settings limits, Usage spending cap, Upstreams, Alerts, and Webhooks away from silent invalid returns or native-validation bypasses.
- Correct the misleading Settings danger zone: separate the browser-local reset/sign-out behavior from real staged account deletion and recovery supported by the API.
- Test keyboard submit, empty submit, malformed/range input, API failure, retry, and success where applicable.

## Task 2: Navigation foundation

**Files:** `src/components/dashboard/nav-config.ts`, dashboard shell/breadcrumb/command-palette components, route wrappers and tests.

- Introduce task-oriented sidebar hubs: Overview, Apps, Jobs, Releases, Instances, Domains, Data, Observe, Billing, and Settings.
- Add reusable secondary navigation for hub pages and app sections.
- Preserve legacy routes and update breadcrumbs and command-palette destinations.
- Normalize visible terminology to Apps while retaining internal workflow route compatibility for now.
- Put owned tab, filter, search, and detail state in the URL where practical.

## Task 3: New App flow

**Files:** new-app wizard, Templates and Import route bodies, compatibility routes, tests.

- Make source choice the first step: Git repository, Empty app, Template, or Import.
- Reuse the existing template catalog and import controls inside the wizard.
- Continue through configuration and review/create without leaving the flow.
- Redirect legacy Templates and Import destinations into the appropriate wizard state.

## Task 4: Jobs hub

**Files:** Jobs, Cron Jobs, and Triggers route bodies/wrappers and tests.

- Compose Workloads, Scheduled requests, and Triggers under one Jobs hub.
- Preserve the distinct backend model and fields of workloads versus scheduled HTTP requests.
- Add deep-linkable job, run, task, schedule, and execution selection where supported.
- Redirect legacy Cron and Trigger routes into their Jobs hub sections.

## Task 5: Releases hub

**Files:** Builds, Deployments, app deployment panels, shared release components, route wrappers, tests.

- Create a unified Releases list showing deployment and joined build state.
- Provide shared detail sections for overview, build output, provenance/SBOM, security scans, deployment lifecycle, runtime controls, and audit context.
- Reuse release detail globally and inside an app.
- Preserve old build and deployment URLs, filters, and selected IDs.

## Task 6: Instance details

**Files:** Instances route/components and tests.

- Open a deep-linkable detail view from an instance row.
- Display all useful existing API fields: state, durations, app, deployment, execution mode, host IP, memory, lifecycle timestamps, minimum target, failure reason, and wake timeline.
- Link to relevant app, release, logs, and debugger contexts when identifiers exist.
- Do not fabricate CPU, network, or host telemetry not returned by the API.

## Task 7: API keys and invitations

**Files:** API Keys and Team/Members route components, shared disclosure/secret components, tests.

- Make tables primary and reveal create/invite forms from explicit buttons using reduced-motion-safe animation.
- Include rotation policy and grace-window context in key creation/rotation flows, clearly describing its scope.
- Mask one-time keys and invitation tokens by default with Copy, Reveal/Hide, and Dismiss controls.
- Clear plaintext UI state on dismissal and navigation.
- Reuse the pattern for personal and organization keys.

## Task 8: Settings and organization restructuring

**Files:** Settings, Team, Account, Security, API Keys bodies/wrappers, organization hooks/mock handlers, tests.

- Focus Members on membership, roles, invitations, and ownership visibility.
- Organize Settings into General, Organization, Members, API keys, Security, Integrations, Platform limits, and Data and privacy.
- Move organization identity, seats/plan summary, transfer, creation, and deletion out of Team.
- Separate personal and organization key scopes while sharing implementation.
- Clearly label browser-local preferences as local and wire supported staged deletion/restore behavior.

## Task 9: Debugger redesign

**Files:** Debugger route/components and tests.

- Structure request investigation around What happened, Why, and What to inspect next.
- Add failure, latency, cold-start, and regression filters from existing data.
- Present a span timeline/waterfall and highlight critical or blamed spans when supported.
- Show app, release, build, route, request, trace, wake, and timestamp context with relevant cross-links.
- Add safe support-bundle copy and regression drilldown/comparison details.
- Use deterministic suggested checks from stable statuses only; do not claim unsupported diagnoses or replay capability.

## Task 10: Cross-console polish

**Files:** shared resource table/empty-state/action components, affected routes, tests.

- Support rich empty-state actions.
- Add discoverable tooltips for icon-only controls.
- Improve narrow-screen table behavior with priority columns and row details/cards.
- Standardize loading, empty, error, permission, and stale states.
- Preserve operational filters in URLs and audit destructive-action wording.
- Extract oversized route bodies opportunistically and remove duplicate app-resource implementations.
- Finish controlled user-facing Apps/Functions/Workflows terminology normalization.

## Completion Gate

- All task-scoped reviews approve spec compliance and code quality.
- A whole-branch review has no unaddressed load-bearing findings.
- `npm run build` succeeds.
- `npm run check` succeeds with zero test failures and no warnings above the repository's accepted lint ceiling.
- Git diff and history show only intentional, atomic changes.
